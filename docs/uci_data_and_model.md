# UCI Online Retail — Data and Model Audit

## المصدر

- Dataset: UCI Online Retail.
- DOI: `10.24432/C5BW33`.
- License: CC BY 4.0.
- المصدر الرسمي: UCI Machine Learning Repository.
- الفترة: ديسمبر 2010 إلى ديسمبر 2011.
- المصدر معاملات بيع فعلية لمتجر إلكتروني بريطاني، وليس بيانات مولدة للمشروع.

## قواعد التنظيف

1. الاحتفاظ بالملف الخام دون تعديل وتسجيل SHA-256.
2. إزالة الصفوف المتطابقة فقط مع تسجيل العدد.
3. تحويل التاريخ والكمية والسعر مع رفض الصف غير القابل للتحويل.
4. اعتبار رقم الفاتورة الذي يبدأ بـ C أو الكمية السالبة عملية إلغاء/إرجاع.
5. حساب قيمة الصف `Quantity × UnitPrice`.
6. فصل إجمالي البيع والإرجاع ثم حساب صافي اليوم.
7. إنشاء تقويم يومي متصل، مع `observed_day=0` لليوم غير الموجود. اليوم غير المرصود لا يسجل كمبيعات فعلية.
8. تسجيل SHA-256 للملف المعالج.

## التدريب

يتم التقسيم زمنيًا دون Shuffle. آخر 56 يومًا — أو 20% عندما تكون البيانات أقصر — للاختبار. تتم مقارنة:

- Seasonal Naive 7.
- Moving Average 7.
- Ridge Regression بميزات lag 1/2/3/7/14/28، متوسط 7/28، يوم الأسبوع، الشهر والاتجاه.

يختار النظام أقل WAPE، ويسجل MAE وRMSE وWAPE وsMAPE لكل نموذج. فواصل التوقع مأخوذة من quantiles لبواقي الاختبار الزمني، واحتمال الانخفاض مشتق من موضع الفرق عن خط الأساس داخل توزيع خطأ الاختبار.

## SQLite

SQLite هي قاعدة المشروع الأكاديمي الأساسية. محليًا تحفظ في `instance/sales_sentinel.db`. على Vercel تستخدم `/tmp` وتعد نسخة عرض مؤقتة؛ لذلك تقييم المشروع النهائي وتشغيل الاستيراد الدائم يتمان محليًا.

## القيود

- البيانات من متجر واحد في المملكة المتحدة؛ لا تدّعي تمثيل السوق السعودي.
- العملة الأصلية جنيه إسترليني.
- التوقع دعم قرار، وليس ضمانًا للمبيعات.
- لا تُستخدم البيانات بعد تاريخ الاختبار في تدريب النماذج عند حساب المقاييس.
